# Troubleshooting

## Installation Issues

### `ModuleNotFoundError: No module named 'eccodes'`

cfgrib requires the `eccodes` C library.

**Local:**
```bash
# macOS
brew install eccodes

# Ubuntu
sudo apt-get install libeccodes-dev
```

**Docker:** Ensure `libeccodes-dev` is in the builder stage and `libeccodes2` is in the runtime stage of the `Dockerfile`. Both are included by default.

---

### `OSError: HDF5 library version mismatch`

Multiple versions of HDF5 on your system. Fix by ensuring only one version is installed:

```bash
# macOS — remove conflicting versions
brew unlink hdf5 && brew install hdf5@1.12 && brew link hdf5@1.12 --force

# Ubuntu
sudo apt-get install --reinstall libhdf5-dev
```

---

### `ImportError: libgeos_c.so.1: cannot open shared object file`

GEOS is not installed or not on the library path.

```bash
# Ubuntu
sudo apt-get install libgeos-c1v5

# macOS
brew install geos
export DYLD_LIBRARY_PATH=$(brew --prefix geos)/lib
```

---

### `pip install pyart-mch` fails with compiler errors

You need C build tools:

```bash
# Ubuntu
sudo apt-get install gcc g++ python3-dev

# macOS
xcode-select --install
```

---

## Docker Issues

### `docker compose up` — containers exit immediately

Check logs:
```bash
docker compose logs web
docker compose logs worker
```

**Common causes:**
- `.env` file missing → `cp .env.example .env` and fill in values
- `SECRET_KEY` is empty → add any string
- Database not ready → the `depends_on` healthcheck should handle this, but try `docker compose up db redis` first, then `docker compose up`

---

### `web` container starts but shows a Django error page

```bash
docker compose run --rm web python manage.py check
```

If it reports missing migrations:
```bash
docker compose run --rm web python manage.py migrate
```

---

### `worker` or `beat` crashes with `redis.exceptions.ConnectionError`

Redis is not reachable. Verify:
```bash
docker compose ps redis  # should be "Up (healthy)"
docker compose exec redis redis-cli ping  # should return PONG
```

Check `REDIS_URL` and `CELERY_BROKER_URL` in `.env` use `redis` (the Docker service name) not `localhost`.

---

## Data Issues

### Map loads but no MRMS tile appears

The MRMS tile is generated by the `poll_mrms_mosaic` Celery task. Check:

1. Is Beat running?
   ```bash
   docker compose ps beat  # should be "Up"
   ```

2. Is the worker consuming tasks?
   ```bash
   docker compose logs worker | grep poll_mrms
   ```

3. Trigger manually:
   ```bash
   docker compose run --rm web python manage.py test_mrms
   ```

4. Check S3 connectivity (NOAA public):
   ```bash
   docker compose run --rm web python -c "
   from apps.radar.services.s3 import get_latest_mrms_key
   print(get_latest_mrms_key('reflectivity'))
   "
   ```
   Should print an S3 key. If `None`, there's a network issue.

---

### Station selected but no radar tiles appear after 2 minutes

1. Check the worker log:
   ```bash
   docker compose logs -f worker
   ```
   Look for `process_nexrad_scan` entries. If missing, the task isn't being queued.

2. Check `ActiveStation`:
   ```bash
   docker compose run --rm web python manage.py shell -c "
   from apps.radar.models import ActiveStation
   from django.utils import timezone
   print(ActiveStation.objects.filter(expires_at__gt=timezone.now()).values('station__code', 'expires_at'))
   "
   ```

3. Check scan downloads:
   ```bash
   ls /tmp/wxradar/scans/  # local
   # or
   docker compose exec web ls /app/data/scans/
   ```

4. Force a station scan:
   ```bash
   docker compose run --rm web python manage.py shell -c "
   from apps.radar.tasks import check_station_for_new_scans
   check_station_for_new_scans.apply(args=['KTLX'])
   "
   ```

---

### `RadarScan` records created but `processed=False` forever

The `process_nexrad_scan` task failed. Check the worker log for the specific error. Common causes:

| Error | Fix |
|-------|-----|
| `pyart not installed` | `pip install pyart-mch` |
| `File not found` | Scan file download failed — check `local_path` in DB |
| `IndexError in grid_from_radars` | Scan file may be corrupted — delete and re-download |
| `MemoryError` | Server ran out of RAM during gridding — reduce `--concurrency` |

---

### NWS alerts layer is empty

1. Verify the NWS API is reachable:
   ```bash
   curl -H "User-Agent: (test, test@example.com)" \
        https://api.weather.gov/alerts/active | python -m json.tool | head -20
   ```

2. Check `NWS_USER_AGENT` is set in `.env` — NWS blocks requests without a proper User-Agent.

3. Check `poll_nws_alerts` in worker log.

4. If there are genuinely no active alerts in the US, the layer will be empty — this is correct behavior.

## Performance Issues

### NEXRAD processing takes > 5 minutes per scan

`grid_from_radars` is the slow step. To speed it up:
- Reduce grid resolution: change `grid_shape=(20, 250, 250)` in `processor.py` (trades detail for speed)
- Increase Celery concurrency: `--concurrency 8` in `docker-compose.yml`
- Use a faster server (Py-ART benefits from more CPU cores)

---

### Disk filling up

Check data directory sizes:
```bash
docker compose exec web du -sh /app/data/*
```

The `cleanup_old_data` task runs hourly but only cleans up files for inactive stations. If a station has been left active, its scan files accumulate.

Force cleanup:
```bash
docker compose run --rm web python manage.py shell -c "
from apps.radar.tasks import cleanup_old_data
cleanup_old_data.apply()
"
```

Or deactivate all stations:
```bash
docker compose run --rm web python manage.py shell -c "
from apps.radar.models import ActiveStation
ActiveStation.objects.all().delete()
print('All stations deactivated')
"
```

## Database Issues

### `django.db.utils.OperationalError: no such table`

Migrations haven't been applied:
```bash
docker compose run --rm web python manage.py migrate
```

---

### `django.db.utils.ProgrammingError: relation "radar_radarstation" does not exist`

Same as above — run migrations. This can happen if the `db` volume was wiped.

---

### PostgreSQL connection refused

Check the `db` service:
```bash
docker compose ps db  # should be "Up (healthy)"
docker compose logs db
```

Verify `DATABASE_URL` in `.env` uses `db` (Docker service name) not `localhost`.

---

## Viewing Logs

```bash
# All services
docker compose logs -f

# Specific service
docker compose logs -f worker
docker compose logs -f beat
docker compose logs -f web

# Last 100 lines
docker compose logs --tail=100 worker
```

Log level for `apps.radar` is `DEBUG` (shows every task step). Log level for Celery is `INFO`.
